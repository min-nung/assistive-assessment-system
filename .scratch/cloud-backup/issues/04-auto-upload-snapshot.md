# 04 — 自動上傳快照

**What to build:** 治療師填寫評估資料後，不需按任何按鈕，資料就自動備份到他自己的 Google Drive。

治療師停止操作 5 秒後，系統自動將完整快照上傳。連續打字期間不重複上傳——每次新變動都重新計時，避免浪費行動網路流量與電力。切換到其他應用程式或鎖上螢幕時，尚未送出的變動立即強制上傳，補足「改完馬上關掉」的空窗。

上傳涵蓋所有資料變更，不只是表單欄位——新增個案、刪除個案、重新命名個案同樣觸發。

Drive 上只維護**單一檔案**，內含全部個案，且檔案在使用者的雲端硬碟中**可見、可自行下載**。系統以固定檔名搜尋既有檔案再更新，避免瀏覽器資料被清除後產生重複檔案。

快照格式直接沿用既有手動匯出的格式，不另創新格式。

離線時不嘗試上傳，顯示「離線，待恢復連線後上傳」，並在恢復連線後自動補傳。上傳失敗時顯示失敗狀態而非假裝成功——治療師必須能判斷是否需要手動匯出 JSON 作為保險。暫時性失敗以指數退避自動重試並設上限，持續失敗則進入明確的失敗狀態，不無限重試。

何時該上傳、何時該等待，全部交由 02 的決策模組判斷；這張票只負責依照決定執行。

**Blocked by:** 02 — 同步決策模組與測試環境；03 — 連結 Google 帳號

**Status:** ready-for-agent

- [ ] 修改評估欄位後停止操作 5 秒，快照自動上傳，過程中不需按任何按鈕
- [ ] 連續輸入期間不會重複上傳，計時隨每次變動重置
- [ ] 切換應用程式或鎖定螢幕時，待傳變動立即送出
- [ ] 新增、刪除、重新命名個案同樣觸發上傳
- [ ] Drive 上只出現一個快照檔案，重複上傳為更新而非新增
- [ ] 使用者可在自己的 Google Drive 中看到並下載該快照檔案
- [ ] 瀏覽器資料被清除後重新連結，系統找到既有檔案並更新，不產生第二份
- [ ] 上傳成功後顯示最後上傳時間
- [ ] 離線時顯示離線狀態，不嘗試上傳，恢復連線後自動補傳
- [ ] 上傳失敗時顯示失敗狀態，不顯示為成功
- [ ] 暫時性失敗會自動重試，重試次數有上限
- [ ] 上傳期間應用程式維持可操作，不阻斷評估工作
- [ ] 上傳的快照格式與既有手動匯出格式一致
