# 06 — 衝突偵測與使用者選擇

**What to build:** 防止一台裝置的舊資料靜默覆蓋掉另一台裝置的新評估成果。

這張票兌現 [ADR 0002](../../../docs/adr/0002-user-resolves-conflicts.md)，處理的是真實且常見的情境：治療師上午用平板在案家評估並上傳快照，下午回辦公室開電腦時，電腦的本機資料仍停留在數日前。若系統直接上傳本機快照，上午的評估成果就會被覆蓋——而且**使用者不會看到任何錯誤**，只會在數日後發現資料消失，屆時雲端上的正確版本早已不存在。

系統在兩個時機比對雲端快照版本：**應用程式啟動時**，以及**每次上傳前**。任一時機發現雲端快照比本機最後一次上傳更新，即進入衝突狀態並**立即停止自動上傳**。

衝突發生時，清楚呈現兩份快照各自的時間與個案數量，由治療師選擇保留本機、採用雲端，或先不決定。治療師選擇「稍後再說」時，應用程式維持完全可用，但在衝突解決前**絕不自動上傳**——猶豫不該導致資料被覆蓋。

系統**一律不自動合併**兩份快照。在現有資料模型下，「同一個案的不同評估模組被兩台裝置分別修改」沒有安全的合併方式，正確合併需要完整的 CRDT，遠超出備份功能的範圍。讓治療師看見兩份並自行選擇，是誠實的做法。

採用雲端快照前，同樣先自動匯出本機資料作為保險。

**Blocked by:** 05 — 從雲端取回快照

**Status:** ready-for-agent

- [ ] 應用程式啟動時比對雲端快照版本
- [ ] 每次上傳前再次比對雲端快照版本
- [ ] 雲端快照較新時進入衝突狀態，且不執行上傳
- [ ] 衝突提示中同時顯示本機與雲端各自的時間與個案數量
- [ ] 可選擇保留本機，選擇後以本機快照覆蓋雲端
- [ ] 可選擇採用雲端，選擇後本機資料被雲端快照取代
- [ ] 採用雲端前先自動匯出一份本機資料的 JSON 檔
- [ ] 可選擇稍後再決定，應用程式維持完全可用
- [ ] 衝突未解決期間，自動上傳完全停止，不會覆蓋雲端資料
- [ ] 衝突未解決期間，狀態列明確顯示「有待處理的衝突」
- [ ] 衝突解決後自動上傳恢復正常運作
- [ ] 系統在任何情況下都不會自動合併兩份快照
