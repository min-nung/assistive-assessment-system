# 02 — 同步決策模組與測試環境

**What to build:** 一個純函式模組，回答唯一的問題：「以現在的情境，雲端備份下一步該做什麼？」

它接收一份描述當下狀態的純資料（是否已連結、是否在線、本機最後變動時間、最後成功上傳時間、雲端快照時間、距離最後變動經過多久、是否有未解決的衝突、觸發原因），回傳一個決定：`idle`、`upload`、`wait`、`conflict`、`needs-auth` 或 `offline`。

這個模組不碰網路、不碰 DOM、不碰 localStorage、不讀取當下時間——時間由呼叫端傳入。所有可能導致資料靜默遺失的判斷都集中在此，因此它是整個功能唯一需要自動化測試覆蓋的部分。

同時建立本專案的第一組測試：使用 Node 內建的 `node:test` 與 `node:assert`，不引入任何第三方測試框架，維持專案「零依賴、零建置流程」的既有紀律。

測試只驗證外部行為——給一組情境，斷言回傳的決定。測試不應知道模組內部如何比較時間或組織條件判斷。測試名稱應以情境敘述，讀起來像規格。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] `npm test` 可執行測試，且不需要 `node_modules`
- [ ] 未連結時回傳 `needs-auth`，且在任何情況下都不回傳 `upload`
- [ ] 離線時回傳 `offline`，且在任何情況下都不回傳 `upload`
- [ ] 距離最後變動未滿 5 秒時回傳 `wait`
- [ ] 距離最後變動已滿 5 秒時回傳 `upload`
- [ ] 觸發原因為使用者離開頁面時，即使未滿 5 秒仍回傳 `upload`
- [ ] 雲端快照時間比本機最後上傳時間新時回傳 `conflict`，而非 `upload`
- [ ] 存在未解決的衝突時，任何情境都不回傳 `upload`
- [ ] 雲端尚無快照且本機有個案資料時回傳 `upload`
- [ ] 本機自最後一次上傳後無任何變動時回傳 `idle`
- [ ] 應用程式啟動為觸發原因且雲端較新時回傳 `conflict`
- [ ] 邊界情境有測試覆蓋：兩邊時間戳相同、時間戳缺失、雲端檔案不存在
- [ ] 模組為純函式：相同輸入永遠得到相同輸出，無副作用
