# 07 — 備份狀態可見性與提醒整合

**What to build:** 讓治療師隨時能一眼看出資料現在到底有沒有受到保護。

前面幾張票各自做了「夠用就好」的狀態顯示。這張票把它們統整成一致的狀態呈現，並整合手動與雲端兩套備份的提醒邏輯。

這件事之所以重要，是因為雲端備份最糟的失敗模式是**靜默失效**：治療師因為信任雲端而不再手動匯出 JSON，卻沒察覺備份其實已經停了數週，結果兩邊都沒有保護。Google OAuth 同意畫面處於測試模式時，授權約 7 天就會失效，這個情境非常真實。

既有的資料備份面板應同時呈現手動備份與雲端備份的狀態，讓治療師在同一個地方掌握全部資訊，而不是兩套各說各話。雲端狀態需明確區分：已連結且正常、離線待補傳、上傳失敗、需要重新連結、有待處理的衝突。

雲端備份正常運作時，不再顯示既有的 7 天手動備份提醒——否則兩套系統重複打擾，提醒會失去意義。但當雲端備份停止運作超過一段時間，則必須主動提醒治療師，讓他能決定改用手動匯出。

所有提醒都不應阻斷正在進行的評估。

**Blocked by:** 06 — 衝突偵測與使用者選擇

**Status:** ready-for-agent

- [ ] 既有備份面板同時顯示手動備份與雲端備份狀態
- [ ] 雲端狀態可區分：正常、離線、上傳失敗、需重新連結、有待處理的衝突
- [ ] 正常狀態顯示最後一次成功上傳的時間
- [ ] 雲端備份正常運作時，不再顯示 7 天手動備份提醒
- [ ] 雲端備份停止運作超過設定天數時主動提醒
- [ ] 從未連結雲端備份的使用者，維持既有的 7 天手動提醒行為
- [ ] 所有狀態提示不阻斷評估操作
- [ ] 狀態在連結、上傳、失敗、解除連結後即時更新，不需重整頁面
- [ ] 手動 JSON 匯出與匯入功能維持可用，未被雲端備份取代
