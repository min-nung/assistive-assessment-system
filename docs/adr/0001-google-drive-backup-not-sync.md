# 以 Google Drive 作為雲端備份，而非多裝置同步

## 背景

本系統原本僅將個案資料保存在瀏覽器 localStorage，並倚賴使用者手動匯出 JSON 備份。這對臨床使用而言風險過高——清除瀏覽器資料、裝置遺失或損壞都會造成評估資料永久遺失，而 7 天一次的手動備份提醒經常被忽略。

## 決定

採用 Google Drive 保存快照，且明確定位為**備份**而非**同步**。localStorage 仍是唯一真相來源；雲端資料只在使用者明確選擇時才會取代本機資料。

不採用 Firebase 或自建後端。

## 理由

**個資責任歸屬**是決定性因素。個案評估資料包含病史、身體尺寸、壓傷狀態等敏感個人資料。若採用 Firebase 或自建後端，這些資料會存放在本專案管理的伺服器上，使專案方成為個資的保管者，須承擔相應的法律責任與安全義務。採用使用者自己的 Google Drive，資料始終留在使用者本人的帳號中。

次要理由是本系統為純靜態網頁應用，無建置流程、無後端。Drive 方案不需要引入伺服器，也不破壞既有的離線優先架構。

## 後果

**Google Drive 無法做到多裝置即時同步，這是刻意接受的限制。** Drive 沒有資料變更的推播機制，因此 A 裝置的變更不會主動通知 B 裝置——B 只能在開啟應用程式時主動比對。若未來確實需要即時同步或跨治療師共享個案，本決定必須推翻，屆時應重新評估 Firebase 或自建後端。

由於快照可能被另一台裝置覆蓋，系統必須在啟動時與上傳前各檢查一次雲端版本，並在偵測到衝突時交由使用者選擇保留哪一份，一律不自動合併。詳見 [0002](./0002-user-resolves-conflicts.md)。
