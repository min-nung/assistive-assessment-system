# 衝突一律由使用者決定，不自動合併

## 背景

即使是單人使用，衝突仍會發生且屬於正常使用路徑：治療師上午用平板在案家評估並上傳快照，下午回辦公室開電腦時，電腦的 localStorage 仍停留在數日前的狀態。若應用程式直接上傳本機快照，將覆蓋掉上午的評估成果。

此類失敗是**靜默**的——使用者不會看到任何錯誤，只會在數日後發現資料消失，而屆時雲端上的正確版本早已被覆蓋。

## 決定

在兩個時機檢查雲端快照的版本：**應用程式啟動時**，以及**每次上傳前**。偵測到雲端快照較新時，一律停下來詢問使用者要保留哪一份，絕不自動合併，也絕不直接覆蓋。

## 理由

在本系統的資料模型下，「合併」沒有安全的定義。兩台裝置可能各自修改了**同一個個案**的不同評估模組——一台填寫輪椅、一台填寫氣墊床。要正確合併需記錄每個欄位的個別變更時間，等同實作完整的 CRDT，其工程量遠超出「自動備份」的範圍。

在無法保證合併正確的前提下，讓使用者看見兩份快照並自行選擇，是誠實的做法。資料是個案的臨床評估紀錄，寧可要求使用者多做一次判斷，也不該讓程式猜錯而靜默遺失資料。

此決定與系統既有的態度一致：刪除個案會要求確認，匯入備份會明確告知「目前的 N 筆個案會被取代」。

## 後果

使用者偶爾會遇到需要手動選擇的中斷。這是刻意的成本，不應為了流暢度而移除。

任何未來要加入自動合併的提案，都必須先解決「同一個案、不同評估模組被並行修改」這個情境，否則不予採納。
